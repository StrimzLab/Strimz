The Strimz API is a single host (`https://api.strimz.finance`) serving JSON over HTTPS. Every endpoint is documented in [OpenAPI](https://api.strimz.finance/openapi.json) and rendered by [Scalar](https://api.strimz.finance/docs) for an interactive "try it" experience.

## Base URL

```
https://api.strimz.finance
```

That's live mode, on Arc mainnet, for `sk_live_` keys. Test mode, on Arc testnet, is at
`https://api-test.strimz.finance` for `sk_test_` keys. The SDKs choose the right one from your
key. See [Authentication](/docs/authentication) and [Test mode and live mode](/docs/testing).

## Authentication

```http
Authorization: Bearer sk_test_xxx
```

See [Authentication](/docs/authentication) for the full breakdown.

## Errors

Every error returns a JSON envelope:

```json
{
  "error": {
    "code": "invalid_request",
    "message": "amount must be a positive integer string",
    "param": "amount",
    "details": { "issues": [...] },
    "requestId": "req-4f2"
  }
}
```

The full code list is on [Errors](/docs/errors). Always include the
`requestId` when reporting an issue; it's the key support uses to
find your request in the logs.

## Pagination

List endpoints return:

```json
{
  "data": [...],
  "nextCursor": "cmh3lmkw50000xv8d12345678",
  "hasMore": true
}
```

Pass `?cursor=<nextCursor>` on the next call. `limit` defaults to 25, max 100.

## List filters

Filters like `status`, `kind`, `outcome` and `eventName` take one value or a comma-separated list of up to 20. A list matches any of its values:

```http
GET /v1/payment-sessions?status=confirmed,expired
```

An unknown value returns `400 invalid_request`.

Transactions, payment sessions, subscriptions, invoices, refunds, webhook deliveries and agent activity also take `from` and `to`: ISO-8601 timestamps with a time zone, where `from` is included and `to` is not. Transactions filter on when the payment settled; the others on when the record was created.

```http
GET /v1/invoices?from=2026-10-01T00:00:00Z&to=2026-11-01T00:00:00Z
```

## Idempotency

Send an `X-Strimz-Idempotency-Key` header on a `POST` or `PATCH` and the API replays the first response for that key for 24 hours. The SDK sends one on every write. See [Idempotency](/docs/concepts/idempotency).

## Rate limits

The API allows 600 requests per minute per IP across all routes. Some routes have a tighter limit of their own. Exceeding a limit returns `429`.

## Resources

Every resource has its own page in the sidebar. The most-used ones:

- **[Payment sessions](/docs/api/payment-sessions).** One-shot checkouts.
- **[Subscriptions](/docs/api/subscriptions).** Recurring revenue.
- **[Refunds](/docs/api/refunds).** Server-intent plus wallet-signed transfers.
- **[Webhooks](/docs/api/webhooks).** Register endpoints, replay deliveries.
- **[Invoices](/docs/api/invoices).** Invoices with line items, paid through checkout.

## Try it

A one-line sanity check against the test API:

```bash
curl https://api-test.strimz.finance/v1/merchants/me \
  -H "Authorization: Bearer sk_test_xxx"
```
