Subscriptions are bound to a `SubscriptionPlan` (the template) and a `Customer` (the buyer). The customer's wallet authorises a multi-period allowance; Strimz's scheduler charges every period.

## Plans

```http
POST /v1/subscription-plans
{
  "name": "Pro",
  "amount": "20000000",
  "currency": "USDC",
  "interval": "monthly",      // 'daily' | 'weekly' | 'monthly' | 'quarterly' | 'yearly'
  "intervalCount": 1,
  "trialPeriodDays": 14
}
```

```http
GET  /v1/subscription-plans/{id}
GET  /v1/subscription-plans
```

## Subscriptions

Customers create subscriptions on-chain via your hosted checkout. There's no `POST /v1/subscriptions` endpoint. The indexer projects them when the chain emits `SubscriptionCreated`.

Read paths:

```http
GET  /v1/subscriptions/{id}
GET  /v1/subscriptions?status=active&planId=cmq4wjr3m0008je6l5t0w2yhb
POST /v1/subscriptions/{id}/cancel    { "reason": "merchant initiated" }
```

The list also takes `customerId` to show one customer's subscriptions.

Cancel marks the subscription `cancelled` in Strimz right away and queues the on-chain cancel.

That on-chain cancel works with the subscriptions contract from the next testnet redeploy ([#142](https://github.com/StrimzLab/strimz/issues/142)). On the current deployment it reverts, so the subscription stays active on-chain.

## Status enum

```
trialing  active  at_risk  cancelled  lapsed
```

Only `cancelled` and `lapsed` are terminal; `at_risk` is recoverable if the customer tops up their wallet. The schema also lists `paused`, but there are no pause or resume routes and nothing sets it today.

## Charges

Charges are written by the indexer from on-chain events. There are no charge routes in the API. Follow charges through the `subscription.charged` and `subscription.charge_failed` webhooks, or in the dashboard.

## Webhook events

| Event                        | Fires when                              |
| ---------------------------- | --------------------------------------- |
| `subscription.created`       | A new on-chain subscription is observed |
| `subscription.charged`       | A periodic charge succeeded             |
| `subscription.charge_failed` | A charge attempt failed                 |
| `subscription.cancelled`     | The merchant or customer cancelled      |
| `subscription.lapsed`        | Grace period exceeded                   |
