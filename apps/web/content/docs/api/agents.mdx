## Read config

```http
GET /v1/agents/config
```

Returns the current `AgentMerchantConfig`. If you've never touched it, it's lazy-created with defaults on first read.

## Update config

```http
PATCH /v1/agents/config
{
  "enabledCapabilities": ["recovery", "cashflow", "pricing_intelligence"],
  "recovery": {
    "gracePeriodHours": 48,
    "strategy": "twice",
    "notificationTemplate": "Hey, your subscription with us couldn't be charged. Top up?"
  },
  "cashflow": {
    "digestEnabled": true,
    "anomalySensitivity": "medium",
    "autoConvertToYield": false,
    "minimumLiquidReserveCents": 50000
  },
  "commerce": {
    "requireHumanApprovalAboveUsdCents": 100000,
    "approvedVendors": ["0x..."],
    "monthlySpendCapUsdCents": 500000
  }
}
```

Partial update. Only the keys you send are applied.

## Activity log

```http
GET /v1/agents/activity?capability=recovery&outcome=success
```

Returns chronological agent actions. Filter by `capability`, `actionType`, `outcome`, `subscriptionId`, `transactionId`, `jobId`.

`metadata` is a flat object. Token amounts are base-unit strings (6 decimals), one key per currency, and USDC and EURC are never added together; `...Cents` values are USD cents. Reports count live-mode activity only, except commerce (see below).

| `actionType`                                        | Money keys in `metadata`                                                                                                              |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `cashflow_digest_sent`                              | `revenueUsdc`, `revenueEurc`, `feesUsdc`, `feesEurc`, `netUsdc`, `netEurc`, plus `count` and `uniqueCustomers` across both currencies |
| `cashflow_anomaly_flagged`                          | `currency`, `actualRevenue`, `expectedMean`, `stddev` in that currency, plus `zScore`. One row per currency and hour                  |
| `cashflow_yield_converted`                          | `balanceCents`, `surplusCents`, `reserveCents` from USDC only, plus `eurcBalance`                                                     |
| `commerce_job_completed` (`stage: monthly_summary`) | `spendUsdc`, `spendEurc`; `capUtilisationPct` counts USDC only. Commerce jobs carry no mode, so test jobs are included                |

Rows written before 2026-10 carry `revenue`, `fees`, `net` and `totalSpendCents` instead, with both currencies added together.

## Jobs

```http
POST /v1/agents/jobs
{
  "vendorAddress": "0x...",
  "description": "Translate marketing pages",
  "amount": "50000000",
  "currency": "USDC"
}
```

Auto-approves if `amount < commerce.requireHumanApprovalAboveUsdCents`; otherwise creates with status `proposed`.

```http
GET  /v1/agents/jobs
GET  /v1/agents/jobs/{id}
POST /v1/agents/jobs/{id}/approve
```

## Webhook events

| Event                   | Fires when                                |
| ----------------------- | ----------------------------------------- |
| `agent.action_executed` | Any capability completed an action        |
| `agent.job_proposed`    | A job needs human approval                |
| `agent.job_completed`   | A job's escrow was released to the vendor |
| `agent.job_disputed`    | A job was disputed                        |

See [The AutoPay Agent](/docs/guides/agent) for the capability-by-capability breakdown.
