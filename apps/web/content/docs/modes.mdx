---
title: Test mode vs live mode
description: How Strimz separates test traffic from real traffic, end to end.
---

Strimz splits test and live across the entire stack — different smart-contract deployments, different RPC URLs, different Postgres tables, different webhook endpoints, different signing secrets. There is **no** way for a test-mode call to settle a real payment, and there is no merge step to migrate test rows to live. This is intentional.

## Why we separate so aggressively

Most billing bugs aren't bugs — they're "I didn't realise I was hitting prod". Strimz makes that mistake impossible by construction: the `sk_test_` key prefix routes the request to a different chain, a different DB, a different scheduler, and a different agent. If you build a feature in test mode and then point the same SDK call at production by switching the key prefix, the only thing that changes about your code is one constant.

## What's different between modes

| | Test mode | Live mode |
| --- | --- | --- |
| Chain | Arc Testnet (chain ID 5042002) | Arc Mainnet |
| RPC URL | `https://rpc.arc-testnet.example.com` | `https://rpc.arc.example.com` |
| USDC | Arc Testnet USDC (faucet at [faucet.circle.com](https://faucet.circle.com)) | Arc Mainnet USDC |
| Webhook endpoints | Different list per mode | Different list per mode |
| API keys | `sk_test_*`, `pk_test_*` | `sk_live_*`, `pk_live_*` |
| Dashboard view | Mode toggle in topbar | Mode toggle in topbar |

Resources (`Subscription`, `Transaction`, `WebhookDelivery`, etc.) carry a `mode` column so dashboard queries can filter cleanly. The same column gates the scheduler — its sweep query only picks up subs in the mode the scheduler instance is running.

## Switching modes

In your code, you switch modes by changing the API key. The same SDK client works for both:

```ts
const strimzTest = new Strimz({ apiKey: process.env.STRIMZ_TEST_KEY! })
const strimzLive = new Strimz({ apiKey: process.env.STRIMZ_LIVE_KEY!  })
```

In the dashboard, there's a toggle in the topbar. Switching it doesn't migrate anything — it just shows you the data filtered to that mode.

## Webhooks per mode

Webhook endpoints are scoped to a single mode at creation. An endpoint with `mode: 'test'` only receives test events; the same URL can be registered twice (once per mode) if you want. The signing secret is per-endpoint-row, so test and live signatures are different.

## Identity

Your merchant identity (business name, payout address, KYB info) is shared across modes. That's by design — Strimz isn't trying to make you complete two onboardings. But everything *transactional* (sessions, subs, refunds, deliveries, invoices) is mode-segregated.
