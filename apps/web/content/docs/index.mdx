title: Welcome to Strimz
description: B2B subscription billing on stablecoins. Settled in USDC on Arc.
---

Strimz is a billing layer for businesses that accept stablecoin payments.
One API covers one-time payments, recurring subscriptions, refunds, agent
escrow, and cross-chain settlement. Every payment settles in USDC on Arc.
Because USDC is the native gas token on Arc, your customers never have to
top up a wallet just to send a payment.

The API uses verb-noun method names like `paymentSessions.create`,
`subscriptions.cancel`, and `refunds.create`. Webhooks use a `t=…,v1=…`
signature header signed with HMAC-SHA256. The full reference is on
[/docs/api/overview](/docs/api/overview).

What makes Strimz different is what happens on-chain. The smart contract
enforces idempotency itself, so retries can't double-charge anyone.
Settlement is final the moment your webhook fires. There is no three-day
wait, no chargeback window, and no bank that decides to reverse the
transaction a week later.

<Callout title="Live on Arc" type="info">
  All examples in these docs assume Arc — Circle's stablecoin-native L1 where
  USDC is the gas token. Test mode runs on Arc Testnet (chain ID `5042002`).
  See [Modes](/docs/modes) for environment details.
</Callout>

## What's in the box

A complete billing surface, not a payment SDK. Strimz ships every primitive
your team would otherwise build over six engineering quarters.

<Cards>
  <Card title="Hosted checkout" description="Branded one-shot + subscription checkout pages — no client UI to maintain." />
  <Card title="Wallet auth" description="Email, social, or wallet — via Privy. Embedded Arc wallets, automatic 2FA gates." />
  <Card title="Webhook delivery" description="Signed, retried with exponential backoff, replay-protected, auto-disabled after persistent failure." />
  <Card title="Refund pipeline" description="Wallet-signing instructions returned in the create response. Indexer closes the loop." />
  <Card title="Cross-chain" description="CCTP V2 attestation + scheduler-side message replay on Arc — your customer pays from any USDC chain." />
  <Card title="Analytics" description="MRR, churn, conversion, LTV, 90-day forecast — SQL-backed against your own Postgres." />
  <Card title="AutoPay Agent" description="Recovery emails, cashflow digest, anomaly detection, vendor escrow with allowlists." />
  <Card title="Dashboard + storefront" description="Hosted merchant dashboard + a no-code storefront builder so you can sell without an e-commerce stack." />
  <Card title="OpenAPI 3.1" description="Machine-readable schema. Generate clients in any language — Postman, Insomnia, or your own codegen." />
</Cards>

## A note on tone

These docs assume you know what an HTTP request looks like, so we skip the
lectures on what JSON is. We try to get to the curl command quickly. If a
section feels too long or too short, that's worth fixing.

If something is wrong, unclear, or out of date,
[open an issue](https://github.com/StrimzLab/strimz/issues/new). Docs PRs
go through the same review as code PRs.
