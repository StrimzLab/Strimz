The React SDK gives you a provider, hooks, and two components that
open Strimz hosted checkout from your own page. It uses publishable keys (`pk_test_…` and
`pk_live_…`), which are safe to ship in a browser bundle. A publishable key grants no
access: the SDK reads test or live mode from its prefix and calls only the public
`/v1/checkout` and `/v1/tokens` routes, which answer browsers on any origin. See
[Calling Strimz from a browser](/docs/authentication#calling-strimz-from-a-browser).

## Install

```bash
pnpm add @strimz/sdk-react
```

## Provider

Wrap your app once:

```tsx title="app/layout.tsx"
'use client'
import { StrimzProvider } from '@strimz/sdk-react'

export default function Layout({ children }: { children: React.ReactNode }) {
  return (
    <StrimzProvider publishableKey={process.env.NEXT_PUBLIC_STRIMZ_PUBLISHABLE_KEY!}>
      {children}
    </StrimzProvider>
  )
}
```

`StrimzProvider` takes a publishable key, never a secret key. Write
operations, such as creating a payment session, go through your own
backend with the server-side `StrimzClient`, which refuses to start in a browser (see
[Create sessions on your server](/docs/checkout/server-sessions)). The provider also accepts
`apiBaseUrl` to override the API base URL and `checkoutOrigin` to
override the hosted-checkout origin (default `https://strimz.finance`).

## `<StrimzPayButton />`

Drop-in checkout button for an existing session:

```tsx
'use client'
import { useRouter } from 'next/navigation'
import { toast } from 'sonner'
import { StrimzPayButton } from '@strimz/sdk-react'

export function Checkout({ session }: { session: { id: string } }) {
  const router = useRouter()
  return (
    <StrimzPayButton
      sessionId={session.id}
      onSuccess={(txHash) => router.push(`/thanks?tx=${txHash ?? ''}`)}
      onError={(err) => toast.error(err.message)}
    />
  )
}
```

The button opens Strimz hosted checkout for the session, in a popup by
default or as a full-page redirect with `mode="redirect"`. The hosted
checkout uses Reown AppKit to connect a wallet. It then prompts the
customer for two typed-data signatures. The first is an
EIP-3009 `ReceiveWithAuthorization` that authorises USDC (or EURC) to
move. The second is a Strimz `PayIntent` that binds the payment to
this specific merchant, amount, and session. `onSuccess` receives the
on-chain transaction hash when the checkout reports success. Treat it
as a UI signal only: your webhook is the source of truth for
fulfilment.

The `PayIntent` signature is what stops an intercepted EIP-3009 auth
from being replayed to a different merchant. Same story on
subscriptions: the wallet prompts once for the EIP-2612 permit and
once for a `SubscriptionIntent` that pins the plan.

## `<StrimzCheckoutEmbed />`

For a full embedded checkout (no redirect):

```tsx
<StrimzCheckoutEmbed
  sessionId={session.id}
  className="rounded-xl border"
  onSuccess={(txHash) => router.push(`/thanks?tx=${txHash ?? ''}`)}
/>
```

Renders the hosted checkout inline in an iframe. Useful for cart-style flows where you don't want to lose the buyer's context.

| Prop        | Type                        | Default            | Description                                                                        |
| ----------- | --------------------------- | ------------------ | ---------------------------------------------------------------------------------- |
| `sessionId` | `string`                    | required           | The payment session to pay.                                                        |
| `height`    | `number \| string`          | `600`              | Iframe height.                                                                     |
| `theme`     | `'light' \| 'dark'`         | payer's preference | Pins the embedded checkout to light or dark. Omit it to follow the payer's system. |
| `onSuccess` | `(txHash?: string) => void` |                    | Called with the transaction hash after a successful payment.                       |
| `onCancel`  | `() => void`                |                    | Called when the payer cancels.                                                     |
| `onError`   | `(error: Error) => void`    |                    | Called when the checkout reports an error.                                         |
| `className` | `string`                    |                    | Class name for the iframe wrapper.                                                 |
| `style`     | `React.CSSProperties`       |                    | Inline style for the iframe wrapper.                                               |

## Hooks

The package exports three hooks. All of them must be used inside `<StrimzProvider>`.

- `useStrimzSession(sessionId, { pollIntervalMs? })` reads a payment session with the publishable key and polls until it reaches a terminal state (`confirmed`, `failed`, `expired`, or `cancelled`). It returns `{ session, loading, error, refresh }`.
- `useStrimzCheckout({ mode?, onSuccess?, onCancel?, onError? })` is the imperative opener behind `<StrimzPayButton />`. It returns `{ open(sessionId), close(), status }`.
- `useStrimzClient()` returns the provider's `StrimzBrowserClient`.

```tsx
'use client'
import { useStrimzSession } from '@strimz/sdk-react'

function PaymentStatus({ sessionId }: { sessionId: string }) {
  const { session, loading, error } = useStrimzSession(sessionId)
  if (error) return <p>Could not load the payment: {error.message}</p>
  if (loading && !session) return <p>Loading…</p>
  return <p>Status: {session?.status}</p>
}
```

The hooks have no TanStack Query dependency.
