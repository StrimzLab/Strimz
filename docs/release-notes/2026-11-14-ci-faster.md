# Faster CI

The `node` job took 14–17 minutes on every PR: it rebuilt every workspace and all six Next.js apps from scratch, then ran lint, typecheck and test one after another.

- **`build` and `checks` run in parallel.** `checks` (format, lint, typecheck, test) only needs the shared packages built, not the Next.js apps.
- **Turbo's cache is kept between runs** (GitHub Actions cache), so a workspace is rebuilt only when its inputs changed. Next.js's own `.next/cache` is kept as well. Entries older than a week are dropped so the cache doesn't grow without limit.
- **Tests are never cached** (`turbo.json`): several tests read other workspaces' files, which turbo can't see as inputs, so a cached pass could hide a regression.
- **`foundry` runs only when it matters:** on pull requests that touch `packages/contracts`, `apps/indexer` (whose ABIs it checks), the Foundry scripts, submodules or the workflow, and on every push to `main`.
- **`quality` also requires the new `changes` job**, so a broken change detector fails the gate instead of skipping contract checks.

No app code changes. Branch protection still requires only `quality`.
