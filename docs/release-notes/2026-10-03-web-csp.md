# Web: report-only Content-Security-Policy

Every page of `apps/web` now sends a Content-Security-Policy in report-only mode. The
browser blocks nothing; it reports what the policy would have blocked to a new endpoint
in the web app, which writes one log line per violation. After at least one release of
clean reports the policy is switched to enforcing.

Closes #132. ADR: [ADR-2026-10-03-web-security-headers](../adr/ADR-2026-10-03-web-security-headers.md)
([plain-English version](../adr/ADR-2026-10-03-web-security-headers-for-dummies.md)),
accepted 2026-10-03. The rest of #132 shipped in
[2026-10-03-web-security](./2026-10-03-web-security.md).

## Decisions taken on the ADR's open points

- **Report collector: first party.** Reports go to `POST /api/csp-report` in the web
  app and end up in the web app's own logs. No third-party collector receives page URLs.
- **HSTS: deferred.** `Strict-Transport-Security` stays `max-age=63072000`, without
  `includeSubDomains` and without `preload`. Adding them needs every `strimz.finance`
  subdomain checked for HTTPS first, and preload is hard to undo.

## What shipped

- `Content-Security-Policy-Report-Only` on every route, built in
  `apps/web/next.config.mjs`:
  - `default-src 'self'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`.
  - `script-src 'self' 'unsafe-inline' https://auth.privy.io https://challenges.cloudflare.com`.
    `'unsafe-inline'` is needed for the inline scripts the App Router emits; no
    `'unsafe-eval'`.
  - `connect-src`: the app itself, the origin of `NEXT_PUBLIC_API_URL`, the Arc RPC
    origins of every chain in `@strimz/shared-config` (`ARC_CHAINS`), the origin of
    `NEXT_PUBLIC_ARC_RPC_URL` when set, Privy, WalletConnect / Reown, Coinbase Wallet
    and the uploadthing ingest hosts.
  - `frame-src` and `child-src`: Privy, the WalletConnect verify and secure frames, and
    Cloudflare Turnstile.
  - `img-src 'self' data: blob: https:`. Merchant logos and product images are stored
    URLs that are not limited to uploadthing hosts, and wallet icons come from many
    hosts, so any HTTPS image is allowed.
  - `style-src` and `font-src` add the Google and Reown font hosts AppKit uses.
  - `frame-ancestors 'none'` on every route except `/pay/*` and `/sub/*`, which keep
    `frame-ancestors *` so `StrimzCheckoutEmbed` keeps working on merchant sites.
  - `report-uri /api/csp-report` and `report-to csp-endpoint`.
- `Reporting-Endpoints: csp-endpoint="/api/csp-report"` on every route.
- `POST /api/csp-report` accepts the legacy `application/csp-report` body and the
  Reporting API `application/reports+json` batch (up to 100 entries; entries that are
  not `csp-violation` are ignored). Bodies over 64 KiB get 413, other content types 415,
  malformed bodies 400, valid reports 204. No response has a body. Query strings and
  fragments are stripped from logged URLs, values are cut at 512 characters, and the
  script sample and original policy are never logged.

The API and Arc RPC origins are read when Next builds the app, the same moment
`NEXT_PUBLIC_*` values are inlined. A build without `NEXT_PUBLIC_API_URL` leaves the
API origin out of `connect-src` rather than guessing one, so the browser reports every
API call; a malformed value fails the build.

## Reading the reports

Each violation is one JSON line written with `console.warn` by the `/api/csp-report`
function. In Vercel, open the web project's logs and filter on `csp_violation`:

```json
{
  "event": "csp_violation",
  "format": "report-to",
  "documentUri": "https://strimz.finance/pay/ps_123",
  "blockedUri": "https://example-wallet.io/icon.png",
  "effectiveDirective": "img-src",
  "disposition": "report",
  "sourceFile": null,
  "lineNumber": null,
  "columnNumber": null,
  "statusCode": 200
}
```

- `effectiveDirective` and `blockedUri` say which list is missing which origin.
- `blockedUri` of `inline` or `eval` means inline code or `eval`, not a remote host.
- Reports from browser extensions (`chrome-extension:`, `moz-extension:` source files)
  are noise and can be ignored.
- Rejected requests are logged as `csp_report_rejected` with the status and reason only.

## Switching to enforcing

1. Leave report-only on for at least one release.
2. Walk the flows from the ADR's verification list: Privy login, image upload, a payment
   session in a popup and in `StrimzCheckoutEmbed`, and an Arc testnet payment with an
   injected wallet and with WalletConnect. Each should produce no `csp_violation` line.
3. Add any genuine origin the reports show, with a test in
   `apps/web/src/__tests__/next-config-security.test.ts`.
4. Change the header key in `next.config.mjs` from `Content-Security-Policy-Report-Only`
   to `Content-Security-Policy`, keeping `report-uri` and `report-to`, and update the
   test that asserts no enforcing header is sent.
5. Replacing `'unsafe-inline'` with per-request nonces, and limiting who may frame
   checkout to each merchant's registered origins, are separate decisions.

## Not covered

- Not exercised in a real browser. Checked with unit tests, a production build, and
  `curl` against `next start`: the headers on `/pricing`, `/pay/ps_123` and
  `/sub/plan_1`, and the endpoint's 204, 413, 415 and 405 answers.
- HSTS `includeSubDomains` and `preload`, as above.
