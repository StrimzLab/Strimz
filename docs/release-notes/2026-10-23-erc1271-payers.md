# Smart-contract wallet payers (ERC-1271)

Refs #287. ADR:
[ADR-2026-10-23-erc1271-payers](../adr/ADR-2026-10-23-erc1271-payers.md)
([plain-English version](../adr/ADR-2026-10-23-erc1271-payers-for-dummies.md)).

This changes the contracts only. `StrimzPayments` and `StrimzSubscriptions` are immutable, so nothing changes on chain until the #142 redeploy. The API relay and the checkouts keep the old ABI here, because the live testnet contracts still take `{v, r, s}`. They switch with #142, as listed below.

## What shipped

- **Signatures are `bytes`.** `IStrimzPayments.Sig` and `IStrimzSubscriptions.Sig` are gone.
  - `payWithAuthorization(uint256,address,(address,uint256,uint256,uint256,bytes32),bytes32,bytes,bytes)`
  - `permitAndCreateSubscription(uint256,address,uint256,uint32,uint64,uint64,bytes32,(address,uint256,uint256),bytes,bytes)`
  - Intent typehashes, digests, events and the existing errors are unchanged.
- **New library `PayerSignature`.**
  - A payer with code is checked through ERC-1271 (`SignatureChecker.isValidERC1271SignatureNowCalldata`).
  - A payer without code must send 65 bytes `r ‖ s ‖ v`. A `v` of 0 or 1 is read as 27 or 28.
- **Token calls.**
  - A payer without code: the contracts call the same `v, r, s` overloads of `receiveWithAuthorization` and `permit` as before.
  - A payer with code: the contracts pass the bytes unchanged to the FiatToken v2.2 `bytes` overloads, which run ERC-1271.
  - `IERC3009` and `IERC2612` declare both overloads.
- **New errors.** `Payments__InvalidSignature()` and `Subscriptions__InvalidSignature()`: a payer without code sent a token signature that isn't 65 bytes. A bad intent signature still reverts with `…__InvalidIntent()`.
- **`script/e2e.sh`.** It sends the packed `bytes` signatures.

## Checked on Arc testnet

A fork of Arc testnet with a minimal ERC-1271 wallet:

- **USDC** (`0x3600…0000`): the wallet pays through `payWithAuthorization`, and subscribes with a permit and is charged.
- **EURC** (`0x89B5…D72a`): `version()` is 2, and its `bytes` overloads of `receiveWithAuthorization` and `permit` accept the wallet's signature.
- **EIP-7702:** an account whose delegate has no `isValidSignature` is rejected by FiatToken on both overloads today. This change doesn't affect it.

## Ships with #142

These join the list in [2026-10-03-subscription-intent-nonce](2026-10-03-subscription-intent-nonce.md). They go in the same change that points the apps at the redeployed contracts.

1. **Relay ABI** (`apps/api/src/modules/relay/abi.ts`): `authSig`, `permitSig` and `intentSig` become `bytes`.
2. **Relay inputs:**
   - **DTO** (`relay.dto.ts`): the signature fields accept the `{v, r, s}` object or a `0x` hex string of 0 to 4,096 bytes, and output the hex. The object packs as `r ‖ s ‖ v`.
   - **Types and mapping:** `relay.types.ts` replaces `VRSSignature` with `` `0x${string}` ``, and `relay-inputs.ts` and `relay.service.ts` pass it through.
3. **Relay revert decoding** (`relay-revert.ts`): add `Payments__InvalidSignature()` and `Subscriptions__InvalidSignature()`.
4. **Relay gas:**
   - `RelayChainProbe.simulate` becomes an `eth_estimateGas` that keeps the same revert mapping.
   - The job's limit is `max(fixed limit, ceil(estimate × 1.3))`.
   - An estimate above 600,000 gas returns 400 `relay_gas_too_high`.
   - The e2e chain stub needs an `estimateGas`.
5. **Checkout hooks** (`use-pay-checkout.ts`, `use-subscription-checkout.ts`): post the raw `signTypedData` hex and drop `splitSignature`.
6. **Pay page:** remove `isContractAccount`, the `unsupported_wallet` result and its copy from `checkout-result.ts` and `pay/[sessionId]/page.tsx`, and update `checkout-result.test.ts` and `checkout-result-wiring.test.ts`.
7. **Tests that build relay signatures:** `relay-service.test.ts`, `relay-controller.test.ts`, `relay-checkout-idempotency.test.ts`, `relay-attempt-rules.test.ts`, the relay e2e tests and `checkout-submission.test.ts`.
8. **Docs:** `concepts/on-chain-architecture.mdx` says the contract checks "the signer recovered from" the signature, and `concepts/meta-tx-flow.mdx` describes the two signatures. Both should say that a smart wallet is checked through ERC-1271.

## Verification

- **Red first:** `test/Erc1271Payers.t.sol` didn't compile against the old contracts, because the entrypoints took `Sig` structs, not `bytes`.
- **Unit tests, now 12, all green:**
  - A wallet pays.
  - A wallet pays with empty signatures for hashes it approved on-chain.
  - A wallet's intent signed by another key reverts.
  - A wallet's token signature signed by another key reverts in the token.
  - An EOA uses the `v, r, s` overloads, checked with `vm.expectCall`.
  - EOA signatures with a `v` of 0 or 1 work.
  - Wrong-length EOA signatures revert.
  - A wallet subscribes and is charged.
- **Fork tests on Arc testnet USDC:** a wallet pays, and a wallet subscribes and is charged.
- **Existing tests:** they now pass `bytes`. All contract suites pass.
- `./scripts/preflight.sh` passed in full: 221 contract tests and 6 fork tests on Arc testnet.
