# End-to-end suites run in CI

Nothing user-facing changed. The api, scheduler, agent and indexer end-to-end suites
pass again, and CI runs them on every pull request.

Closes #108.

## Why they were failing

CI never ran these suites, so they drifted from the code. No product bug was hidden in
the api, scheduler or agent failures. Each one was a test that still described behaviour
the product had moved on from.

| Suite     | Before          | After   |
| --------- | --------------- | ------- |
| api       | 47 pass, 8 fail | 58 pass |
| scheduler | 17 pass, 5 fail | 31 pass |
| agent     | 22 pass, 1 fail | 24 pass |

The indexer suite had one failure that was a real bug. It is fixed separately in #113.

## What shipped

- The test setup provides the environment variables the apps now require.
- The scheduler chain stub implements every public method of the real chain service.
  The stub is typed against the service, so a new method that the stub lacks is a
  compile error instead of a runtime failure in a test.
- Tests follow the current behaviour: webhook fan-out happens in the scheduler outbox,
  delivery attempts count from 1, charge attempt ids advance after a burned attempt,
  the bridge worker counts polls in the job payload, and agent jobs require the
  commerce capability.
- New scheduler suite for the webhook outbox dispatcher.
- The api smoke test runs as part of the api suite. No config matched it before.
- New `e2e` CI job. The `quality` check now depends on it.

## How the CI job works

The suites start their own Postgres and Redis through testcontainers, so the job needs
no service containers. It sets `DOCKER_HOST` to the runner's Docker socket, because the
`test:e2e` scripts default to the Docker Desktop socket path on macOS.

## Merge order

Merge the fix for #113 first. Until it is on `main`, the indexer step of the new job
fails on the test that reproduces that bug.
